# 최근 기능 추가하기 작성본

## 기능 1. Gemini 기반 AI 상세 해설 기능

### 1. 기능 개요

기존 딥페이크 판별 결과는 판정값과 점수 중심으로 제공되어 사용자가 결과를 해석하기 어려운 부분이 있었다. 이를 보완하기 위해 Gemini API를 활용한 AI 상세 해설 기능을 추가했다. 이 기능은 저장된 딥페이크 분석 결과를 바탕으로 점수 의미, 판정 근거, 분석 한계, 사용자가 추가로 확인해야 할 내용을 한국어로 풀어서 설명해 준다.

### 2. 추가한 이유

딥페이크 탐지 결과는 확률 기반 결과이기 때문에 단순히 `REAL`, `SUSPICIOUS`, `FAKE` 같은 상태만 보여주면 사용자가 결과를 확정적인 증거로 오해할 수 있다. 그래서 AI 해설 기능에서는 탐지 결과가 참고용이며 최종 판단은 원본 출처와 촬영 맥락을 함께 확인해야 한다는 방향으로 안내하도록 했다. 또한 기존 분석 설명을 반복하는 것이 아니라 점수, 근거 부족 여부, 한계, 후속 확인 절차를 보강하도록 설계했다.

### 3. 구현 흐름

사용자가 결과 화면에서 AI 상세 해설을 요청하면 `/api/v1/ai/verifications/{id}/explanation` API가 호출된다. `AiAnalysisApiController`는 먼저 `VerifyService.getOne(id)`로 기존 검증 결과를 조회하고, `SessionUtil.canAccessVerification()`을 통해 현재 사용자가 해당 분석 결과에 접근할 수 있는지 확인한다. 권한 확인이 끝나면 `GeminiAnalysisService.analyze()`를 호출해 Gemini API 요청을 생성한다.

`GeminiAnalysisService`는 `VerifyDTO`에 저장된 판정값, 점수, API 제공자, 원본 분석 JSON을 바탕으로 프롬프트 데이터를 만든다. 이때 Base64 이미지, 히트맵 원본, 오버레이 이미지처럼 너무 큰 데이터는 제거하고, 입력 길이도 제한하여 Gemini 무료 사용량과 응답 안정성을 고려했다. Gemini 응답은 요약, 상세 설명, 한계, 행동 가이드, 신고 문안 등 구조화된 JSON 형태로 받도록 했다.

생성된 결과는 `ai_analysis_result` 테이블에 저장한다. 같은 요청이 반복될 때 불필요하게 Gemini API를 다시 호출하지 않도록 `request_hash`를 만들고, DB에 같은 해설이 있으면 저장된 결과를 재사용한다. 또한 30분 메모리 캐시와 요청 잠금 처리를 두어 같은 분석 결과에 대한 중복 호출을 줄였다.

### 4. 관련 코드

API 진입점은 `kopo.poly.controller.api.AiAnalysisApiController`이다. 저장된 해설 조회는 `GET /api/v1/ai/verifications/{id}/explanation`, 새 해설 생성은 `POST /api/v1/ai/verifications/{id}/explanation`에서 처리한다.

핵심 서비스는 `kopo.poly.service.impl.GeminiAnalysisService`이다. 이 서비스는 Gemini API 요청 생성, 응답 파싱, 오류 코드 매핑, 캐시 조회, DB 저장을 담당한다. DB 연동은 `IAiAnalysisResultMapper`와 `AiAnalysisResultMapper.xml`에서 처리하며, 상세 해설 결과는 `analysis_type = 'EXPLANATION'`으로 구분해 저장한다.

### 5. 예외 처리

Gemini API 키가 없으면 `AI-CONFIG`, 인증 실패는 `AI-AUTH`, 사용량 초과는 `AI-RATE-LIMIT`, 연결 실패는 `AI-CONNECTION`, 응답 파싱 실패는 `AI-RESPONSE`처럼 오류 코드를 나눴다. 컨트롤러에서는 이 코드를 사용자 메시지로 바꿔 반환하므로, 화면에서는 상황에 맞는 안내 문구를 보여줄 수 있다.

### 6. 발표용 설명

최근 추가한 첫 번째 기능은 Gemini 기반 AI 상세 해설 기능입니다. 기존 딥페이크 분석 결과를 사용자가 이해하기 쉽게 설명하기 위해 만들었고, 판정값과 점수만 보여주는 것이 아니라 결과의 의미, 한계, 추가 확인 방법까지 한국어로 안내합니다. 같은 결과를 반복 요청하면 저장된 해설과 캐시를 재사용해 API 호출을 줄였고, 세션 권한 검사를 통해 본인 분석 결과에 대해서만 해설을 볼 수 있게 했습니다.

## 기능 2. Gemini 이미지 2차 검증 기능

### 1. 기능 개요

두 번째로 추가한 기능은 Gemini 이미지 2차 검증 기능이다. 1차 딥페이크 탐지 결과가 Reality Defender 또는 IMD 분석 결과를 기반으로 한다면, 2차 검증은 Gemini가 원본 이미지 자체를 다시 확인하고 1차 판독 결과와 비교하는 기능이다. 사용자는 결과 화면에서 AI 이미지 2차 검증을 실행해 기존 판정과 Gemini의 시각적 판단이 일치하는지 확인할 수 있다.

### 2. 추가한 이유

딥페이크 탐지 모델 하나의 결과만 제공하면 오탐이나 미탐 가능성을 설명하기 어렵다. 그래서 Gemini 이미지 2차 검증을 추가해 1차 판독 결과를 보조적으로 교차 검토하도록 했다. 이 기능은 이미지를 직접 보고 조명, 경계선, 질감 반복, 손상된 구조, 물리적으로 어색한 부분 같은 시각적 단서를 점검한다. 다만 Gemini 역시 확정 판정 도구가 아니므로, 결과는 보조 의견으로 표현하도록 했다.

### 3. 구현 흐름

사용자가 이미지 2차 검증을 요청하면 `/api/v1/ai/verifications/{id}/image-review` API가 호출된다. `AiImageVerificationApiController`는 `VerifyService.getOne(id)`로 기존 검증 결과를 조회하고, 접근 권한을 확인한 뒤 `GeminiImageVerificationService.verify()`를 실행한다.

`GeminiImageVerificationService`는 먼저 검증 결과 ID, 저장된 이미지 object key, MIME 타입, 파일 크기를 확인한다. 지원하는 이미지 형식은 JPEG, PNG, WebP, GIF이며, 이미지가 너무 크거나 저장된 파일을 읽을 수 없으면 Gemini API를 호출하지 않고 오류를 반환한다. 이미지 파일은 `IObjectStorageService.readObject()`를 통해 로컬 저장소 또는 S3 저장소에서 읽는다.

이미지를 읽은 뒤에는 Base64로 변환하여 Gemini Vision 모델에 전달한다. 요청에는 원본 이미지뿐 아니라 1차 탐지 결과의 제공자, 판정값, 점수도 함께 넣어 “이미지 자체를 먼저 검토한 뒤 1차 판독과 비교해 달라”고 지시한다. Gemini 응답은 교차 검증 상태, 종합 결론, 시각적 요약, 확인된 지표, 한계, 토큰 사용량을 포함하는 구조로 파싱된다.

결과는 AI 상세 해설과 같은 `ai_analysis_result` 테이블에 저장하지만, `analysis_type = 'IMAGE_VERIFICATION'`으로 구분한다. 같은 이미지와 같은 1차 결과에 대한 요청은 `request_hash`로 식별하여 이미 저장된 결과가 있으면 다시 Gemini를 호출하지 않고 캐시된 결과를 반환한다.

### 4. 관련 코드

API 진입점은 `kopo.poly.controller.api.AiImageVerificationApiController`이다. 저장된 2차 검증 결과 조회는 `GET /api/v1/ai/verifications/{id}/image-review`, 새 2차 검증 생성은 `POST /api/v1/ai/verifications/{id}/image-review`에서 처리한다.

핵심 서비스는 `kopo.poly.service.impl.GeminiImageVerificationService`이다. 이 서비스는 이미지 파일 검증, 저장소에서 이미지 읽기, Gemini Vision 요청 생성, 응답 파싱, 결과 저장을 담당한다. 저장된 최신 결과 조회는 `IAiAnalysisResultMapper.selectLatestImageVerification()`과 `AiAnalysisResultMapper.xml`의 `analysis_type = 'IMAGE_VERIFICATION'` 조건을 사용한다.

### 5. 예외 처리

이미지를 찾을 수 없으면 `AI-IMAGE-MISSING`, 읽기 실패는 `AI-IMAGE-READ`, 지원하지 않는 이미지 형식은 `AI-IMAGE-TYPE`, 이미지 크기 초과는 `AI-IMAGE-SIZE`로 처리한다. Gemini API 관련 오류는 상세 해설 기능과 마찬가지로 `AI-CONFIG`, `AI-AUTH`, `AI-RATE-LIMIT`, `AI-REQUEST`, `AI-RESPONSE` 등으로 구분한다. 화면에서는 이 오류 코드를 바탕으로 사용자가 재시도해야 하는지, 설정을 확인해야 하는지 알 수 있게 했다.

### 6. 발표용 설명

최근 추가한 두 번째 기능은 Gemini 이미지 2차 검증 기능입니다. 기존 탐지 모델의 판정만 보여주는 것에서 끝나지 않고, Gemini가 원본 이미지를 다시 확인해 1차 분석 결과와 비교하도록 했습니다. 이미지는 저장소에서 읽어 Gemini Vision 모델로 보내고, 결과는 `IMAGE_VERIFICATION` 타입으로 DB에 저장합니다. 이를 통해 사용자는 딥페이크 판정 결과를 한 번 더 참고할 수 있고, 오탐 가능성이나 판단 보류 상황도 더 자연스럽게 설명할 수 있습니다.
